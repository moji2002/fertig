Install

From npm
npm install fertig

Then import it through your bundler:

@import "fertig";
From a CDN
<link rel="stylesheet" href="https://cdn
  .jsdelivr.net/npm/fertig@1
  /fertig.min.css">

No tooling required at all.

The package ships three files. fertig.css is commented source meant to be read and edited; fertig.min.css is what you serve; and fertig.core.min.css is the same sheet without the ARIA component layer, if you only want the elements.

Layout

fertig has no .container. Direct children of <body> are the containers, so page structure is layout.

<body>
  <nav>…</nav>       <!-- full-bleed toolbar, contents on the measure -->
  <header>…</header>  <!-- the paper starts here -->
  <main>…</main>
  <footer>…</footer>
</body>

<nav> becomes a sticky toolbar with a vibrancy blur. It spans the viewport while its contents stay on the text measure, so the bar reads full-width without the text sliding out to the edges.

Frameworks

One wrapper is fine. React, Vue, Svelte and Next render into a mount node, so the shell matches body’s children or the children of a single #root, #app, #__next or [data-fertig] wrapper — no configuration:

<body>
  <div id="root">
    <nav>…</nav>
    <main>…</main>
  </div>
</body>

Deeper than that, or a mount node named something else, and you re-point the shell yourself — it is the only place body > appears:

#shell > * { max-width: var(--w); margin-inline: auto; padding-inline: 1.9rem }
#shell > header, #shell > main, #shell > footer { background: var(--el) }

Width

One measure, --w at 38rem — about seventy characters. Add .wide to a container for 66rem when a table or grid genuinely needs it.

Typography

Body copy is 16px on a 1.65 line height, set on a measure of roughly seventy characters. Code keeps a monospace face, where fixed width actually earns its place.

Text can be bold, italic, a link, highlighted, struck, inserted, an abbr, inline code, ⌘K, or sample output.

Block quotes take an accent rule and mute their text.
<strong> <em> <a> <mark> <s> <ins>
<abbr title="…"> <code> <kbd> <samp>
<blockquote>…</blockquote>

Forms

Fields sink, buttons rise. Checkboxes, radios, ranges and progress bars inherit accent-color, so changing --ac retints every control at once.

<label for="e">Email</label>
<input id="e" type="email" required>

<label for="s">Plan</label>
<select id="s">…</select>

<button type="submit">Submit</button>

Error states use :user-invalid, so they fire after someone has actually typed rather than on page load. The <legend> is styled as a panel title instead of notching the fieldset border — the one piece of default form chrome that always looks broken.

Buttons

A plain <button> is already styled, and type="submit" gets the filled treatment automatically — most forms need no attributes at all.

<button class="primary">Primary</button>
<button data-variant="ghost">Ghost</button>
<button data-variant="link">Link</button>
<button data-icon>⌘</button>

<button data-size="sm">Small</button>
<button data-size="lg">Large</button>
<button data-block>Full width</button>

<button class="primary" data-tone="err">
  Delete
</button>

Links can be buttons too — <a class="primary"> or <a role="button"> pick up the same styling while staying links.

Cards

.card is a raised panel taking an optional <header> and <footer> that bleed to its edges. Cards are columns, so footers align across a row.

Components

The component layer is addressed by ARIA attributes rather than class names. That is not only stylistic: a component can only be styled if it is also announced correctly to assistive technology.

Segmented control

<div role="group">
  <button aria-pressed="true">Day</button>
  <button aria-pressed="false">Week</button>
</div>

Tabs

<div role="tablist">
  <button role="tab" aria-selected="true">
    Preview
  </button>
</div>

The sheet styles the tabs; wiring which panel shows is yours, and takes about five lines of JavaScript.

Switching panels

fertig styles tabs from their ARIA, but it cannot switch them. aria-selected has to be a real attribute for a screen reader to announce the right tab, and CSS cannot set attributes — so anything CSS-only here would look right and announce wrong. This is the whole of it:

document.querySelectorAll('[role=tablist]').forEach(list => {
  const tabs = [...list.querySelectorAll('[role=tab]')];
  const show = tab => tabs.forEach(t => {
    const on = t === tab;
    t.setAttribute('aria-selected', on);
    document.getElementById(t.getAttribute('aria-controls')).hidden = !on;
  });
  tabs.forEach((t, i) => {
    t.addEventListener('click', () => show(t));
    t.addEventListener('keydown', e => {          // arrows, as the role promises
      const d = e.key === 'ArrowRight' ? 1 : e.key === 'ArrowLeft' ? -1 : 0;
      if (!d) return;
      e.preventDefault();
      const next = tabs[(i + d + tabs.length) % tabs.length];
      show(next); next.focus();
    });
  });
});

Every other component in the sheet — menus, dialogs, drawers, toasts, tooltips, disclosures — needs none of this. The audit is on the homepage.

Menu

Built on the native popover API and anchored to the button that opened it — no JavaScript, no positioning library.

    •  
    <button popovertarget="menu">Menu ▾</button>
<div popover id="menu">
  <menu>
    <li><button>New file</button></li>
  </menu>
</div>
    Anchoring uses CSS anchor positioning, which now works in Chromium, WebKit and Firefox alike. Where it is missing the menu centres on screen — usable, just not attached to its button.

    Dialog

    Opened and closed with the command and commandfor attributes, so no JavaScript is needed, and closedby="any" gives it light dismiss.

    <button class="primary" commandfor="d" command="close">Delete</button>

    Disclosure

    A plain <details> is a bordered panel with a rotating caret. Where the browser supports ::details-content it also animates open and closed, which needs interpolate-size to reach a height of auto.

    What counts as a component?

    Anything styled through an ARIA attribute or a native element, with no class required.

    <details>
  <summary>Title</summary>
  <p>Body.</p>
</details>

    Layout utilities, borrowed from Tailwind

    The names are Tailwind's on purpose: if you know them there, they mean the same thing here, so muscle memory carries over.

    .flex  .flex-col  .flex-wrap  .flex-1

    Only the layout handful: no colour, type or sizing scale, and no responsive variants, because those want a build step and this file does not have one. The gap steps are 0, .25, .5, .75, 1 and 1.5rem. The margins are flow-relative — ms and me, never ml/mr — so a toolbar still lands correctly in Persian or Arabic. .grid is the auto-fit grid above; adding .grid-cols-3 pins it to three columns.

<div class="grid grid-cols-3 gap-4">…</div>

    Named accents

    Seven accents ship as a mapping table over the ramps. Put data-accent on any element and everything inside it — links, focus rings, filled buttons, the caret, the selection — follows. It is scoped, so one section can differ from the rest of the page.

    <section data-accent="sage">
  <button class="primary">Save</button>
</section>

    The values are indigo (the default), sky, sage, clay, plum, gold and slate. Each pair is measured: the light tone clears WCAG AA as link text on paper, the dark tone clears it on the dark ground. For anything else, set --ac yourself — that is all these rules do.

    Try these live on the homepage → Move the accent, the radius and the measure and watch real components restyle, with the contrast measured as you go.

    The rest

    TokenControls
    --bgDesktop, behind the window
    --elPaper: page and field backgrounds
    --faceChrome: buttons, panels, code
    --fg / --mutText and secondary text
    --bdHairline colour

    Change --ac and check --on-ac with it. A light accent needs dark text on top; white on a pale accent is the easiest way to fail contrast.

    Recipes

    Your brand accent
    :root {
  --ac:    light-dark(#c2410c, #fb923c);
  --on-ac: light-dark(#fff,    #1a0b02);
}
    Sharp corners
    :root { --r: 0; --rw: 0 }
    Flat, no depth
    :root { --up: none; --up2: none; --dn: none }
    A different font
    :root {
  --f:  "Inter", system-ui, sans-serif;
  --fm: "Berkeley Mono", ui-monospace, monospace;
}
    Wider measure
    :root { --w: 52rem }
    Force a theme
    <html data-theme="dark">
<!-- or "light"; omit to follow the OS -->

    Right-to-left

    Set the direction and the sheet mirrors. There is nothing to configure and no second file to load:

    <html lang="fa" dir="rtl">

    Every inline-direction rule is flow-relative — padding-inline-start, border-inline-start, margin-inline-end, text-align: start, border-start-end-radius — so list markers, blockquote and <aside> accent bars, table gutters, breadcrumb separators, the segmented control's rounded ends and the toolbar's trailing control all move to the correct side.

    Two things cannot be said logically: translate, which moves the switch knob, and the fallback <select> chevron's background position. Both carry a :dir(rtl) rule. The layout utilities follow the same discipline — .ms-auto and .me-auto exist, .ml-auto deliberately does not.

    Verified by rendering a Persian page in both directions and measuring, not by reading the source.

    Building an app with it

    There is a full product screen at app.html — an invoices dashboard built with this sheet and no page CSS whatsoever. It is the honest test: anything that looks wrong there is missing from the library.

    Two things it taught us

    • Form controls are full-width blocks, which is right in a form and wrong in a toolbar. Inside .row they now size to the row, so filter bars and pagination lay out horizontally.
    • An app screen wants more than the 38rem reading measure. Set --w or put .wide on the container.

    Known gaps

    Things a product screen wants that this sheet deliberately leaves out. Each is a component with real behaviour, not a style:

    • No toasts, avatars, empty states or pagination component
    • No big-number treatment for KPIs — a heading in a card is heading sized
    • No sticky table header, and no icons; the demo uses text glyphs

    Numeric columns do work: <td align="right"> is honoured, and tfoot is emphasised as a totals row.

    Browser support

    The policy is a two-year window on browsers, not on CSS: fertig runs in anything released since August 2024 and carries nothing for the ones before it. The CSS itself is older and duller than that — @layer has been cross-engine since 2022, oklch() and color-mix() since 2023, light-dark() since May 2024. The newest thing the sheet requires is @starting-style, cross-engine since August 2024 — nothing it needs shipped inside the last two years. Floor: Chrome 123+, Safari 17.5+, Firefox 129+. Below that you get unstyled but perfectly readable HTML. There is no polyfill, no fallback build and no vendor prefix, with three exceptions that no engine has replaced yet: -webkit-text-size-adjust, the -webkit-text-fill-color autofill repaint, and the progress pseudo-elements.

    Where the floor comes from

    EngineMinimumSet by
    Chrome / Edge123light-dark() (123)
    Safari17.5light-dark(), @starting-style, text-wrap: balance (17.5)
    Firefox129@starting-style, transition-behavior (129)

    Two cosmetic properties sit above that floor on purpose and are not gated: scrollbar-color and accent-color only reached Safari in 26.2. An engine without them paints its own scrollbar and its own checkbox tick, so there is nothing to fall back to and nothing to break.

    Every release is loaded in Chromium, WebKit and Firefox, every button on every page is clicked, and each page is checked for overflow, broken anchors, duplicate ids, unlabelled inputs and console errors.     Cascade layers

    The sheet declares two layers, @layer fertig, fertig-a11y. Anything you write outside a layer beats both regardless of specificity, so overriding a rule never turns into a specificity fight and never needs !important:

    /* this wins over everything in the sheet */
button { background: hotpink }

    Two things people expect to find in that table are not in it, because they are part of the floor rather than enhancements on top of it: @property types the shadow alphas so elevation can transition, and container-type on .card makes every card a query container. Both of the latter are cross-engine and used unguarded; relative colour is in the table above, because the sheet takes its shadow alphas with color-mix instead — same pixels, and three years older.

    It answers to the OS

    • prefers-reduced-motion — all transitions and the disclosure animation stop
    • prefers-reduced-transparency — the toolbar loses its vibrancy blur and goes opaque
    • prefers-contrast: more — hairlines and secondary text darken
    • forced-colors — shadows drop and borders switch to system colours for Windows High Contrast
    • pointer: coarse — controls grow to a 44px minimum target, per WCAG 2.5.8
    • env(safe-area-inset-*) — the sticky toolbar clears the notch
    • update: fast — e-ink and other slow displays never enter a transition in the first place
    • inverted-colors — images are re-inverted so the OS does not invert them twice
    • color-gamut: p3 — a cleaner accent on wide-gamut displays

    Content it cannot predict

    A classless sheet styles markup it has never seen, so it has to survive the awkward cases:

    • A pasted URL wraps instead of widening the page (overflow-wrap)
    • Tables scroll themselves below 40rem rather than pushing the layout sideways
    • Autofilled fields are repainted, so the browser’s yellow never appears — least of all in dark mode
    • Required fields are marked, read-only fields look inert (:required, :read-only)
    • Numerals are slashed and tabular, so 0 and O never trade places
    • Print gets real page margins, no stranded lines, and URLs only for external links

    The demo pages additionally use command / commandfor and closedby to drive dialogs with no JavaScript at all, plus cross-document @view-transition and a scroll-driven reading bar.
